## 三、仍待处理

> **本节是当轮结论，绝大部分已在第七节处置**（更新器换代、bundle id、L10n 框架化、
> 辅助功能、lint、`.roorules`、关于窗口署名等）。第七条里的「未完成」项、以及第八、
> 九节新增的项，才是当前仍然有效的清单。保留本节是为了能对照「当时判了什么」。

### P1 — 会在真实场景里咬人

1. **安装更新失败无提示**（`src/UpdateManager.swift:454`）。
   安装脚本先 `rm -rf` 旧包再 `mv` 新包；若 `/Applications` 需要管理员授权，替换会失败，
   而应用已经 `terminate`，用户看到的是「应用消失了/打不开」。
   建议：脚本失败时 `open` 回旧路径并写一条日志，或改成写入临时目录后由用户手动替换。

2. **公证顺序倒置**（`build.sh:436` 附近）。
   现在是「打包 → 公证 DMG → staple `.app`」，包内 `.app` 没有嵌入票据，
   离线首启动可能被 Gatekeeper 拦。正确顺序：公证 ZIP → staple `.app` → 重新打包。
   当前未配证书，此问题不生效；**启用签名时必须一起改**。

3. **`unzip -Z -1` 只检查了 `..` 与绝对路径**（`src/UpdateManager.swift:364`）。
   zip 里的符号链接如果指向目录外，`ditto -x` 解压时可能写到暂存目录之外。
   需要仓库或 Release 被攻破才可利用，属纵深防御缺口。可加一条检查：
   用 `unzip -Z`（zipinfo）读权限位，拒绝以 `l` 开头的条目，或拒绝目标含 `..` 的链接。

### P2 — 打磨与长期维护

4. **界面截图过期**：`assets/menu.png`（菜单已重构为「动作 / 计时 / 提醒」三层，并新增
   「暂停时机」单选组）、`assets/break-overlay.png`（倒计时 3 秒后淡出、引导语居中）。
   建议在真机上重新截两张，替换后 README 才算准确。

5. **`runProcess` 有理论死锁**（`src/UpdateManager.swift:505`）。
   只在线程结束后才读管道，输出超过 64 KB 会阻塞子进程。`unzip -Z -1` 输出很小，
   实际难触发；若以后用它跑大输出命令，需要改成并发读。

6. **辅助功能**：状态栏图标 `accessibilityDescription: nil`，休息遮罩上的文字没有
   accessibility label。对一个长期驻留菜单栏的应用，VoiceOver 体验是缺失的。

7. **没有格式化/静态检查**：没有 `.swiftformat` 或 `swift-format` 配置，CI 也不 lint。
   代码风格目前靠手写保持一致（本轮检查过：无行尾空格、无 TODO/FIXME）。

8. **`.roorules` 未更新**：仍写「uses swift 5」，也没提到 `ICHRCore` 模块、`Tests/`、
   `scripts/check-l10n.py` 和 CI。它是给 AI 助手看的项目说明，过时会误导后续协作。
   建议补三行：模块划分、构建入口（`./build.sh` / `./build.sh ci`）、验证入口（`swift test` + 文案脚本）。

9. **`.env.example` 缺 `ICHR_VERSION`**：`build.sh` 支持该变量注入版本，样例文件未提及。

10. **关于窗口没有汉化署名**：署名了 deseven / Fikri Karim / boxicons，但没有本 fork 的
    汉化者。MIT 不强制，但符合社区惯例，也方便用户找到你的仓库反馈。

### P3 — 已知取舍，维持现状即可

11. **bundle id 与上游相同**（`wtf.d7.icanhazrepose`）：无法与原版共存；改 id 会让现有用户
    丢设置且需要重装。当前选择「跟随上游」是合理的。
12. **`L10n` 双语言硬编码**：加第三语言要改 70+ 处调用；两语言阶段收益低，维持现状，
    等真要加日语/繁中时再迁 `.lproj`。
13. **自研更新器**（约 500 行）而非 Sparkle：零依赖、体积小；Sparkle 更稳但需要引入框架。
14. **两张视图各自定义了一份 `onChangeCompat`**（`BreakOverlayView.swift` / `CompactBreakOverlayView.swift`
    末尾各 10 行）：可以抽到共享文件，收益很小。

### 8.2 用户拍板后已修

**P1　关掉「允许跳过休息」后，屏幕会被真正锁住。**（已解决）
`OverlayManager.showBreakOverlay` 的面板是 `ignoresMouseEvents = false`、层级
`.screenSaver`、覆盖所有屏幕；而 Esc 热键只在 `allowSkipBreak == true` 时才注册
（`src/OverlayManager.swift:149`），「跳过」按钮也随之为隐藏。结果：既没有 Esc、
没有按钮，又吞掉全屏幕的点击，用户只能等休息结束（短休息最长 10 分钟，长休息 30 分钟）。
这与本 fork 的设计原则「任何全屏强制休息都能 Esc 退出」直接冲突。

**用户决定：Esc 永远可用。** 已实施：

- `OverlayManager` 无条件注册 Esc 热键，触发 `skipBreak(viaKeyboard: true)`；
- `TimerManager.skipBreak(viaKeyboard:)` 把「键盘退出」和「按钮退出」分成两条路径，
  键盘路径永远允许，按钮路径才看设置；
- 设置项从「允许跳过休息 / Allow Skip Break」改成「显示跳过按钮 / Show Skip Button」，
  语义与行为对齐；**存储键仍是 `allowSkipBreak`**，老用户的选择不丢（有测试守着）；
- 按钮隐藏时，两张遮罩都显示「按 Esc 退出 / Press Esc to dismiss」，
  不再让人以为无路可走。

代价：想「强制自己不许跳过」的用户没有这个选项了——这正是「Esc 永远可用」的含义。

**P2　关于窗口的社交图标指向上游。**（已解决）
Ko-fi（deseven 的）、Discord、Reddit 三个入口已从关于窗口删除，只留指向本 fork 的
GitHub 图标；对应的三个 PNG（`res/ui/bx-kofi.png` 等）与 `AppConstants` 里的常量

### 9.2 状态机零测试 —— **已按方案 A 解决**（见第十节）

**P1　`TimerManager` 没有任何自动化测试。**

它是全项目最复杂、最容易出错的部分（三态状态机 + 锁屏/空闲/会议/唤醒四路外部事件 +
遮罩调度），而当时 39 项测试全部落在 `ICHRCore` 的纯函数上。一个具体例子：本轮修的第 5 条
说明，`screenLockedProvider` / `secondsSinceInputProvider` 这两个注入点从来没有测试用过。

为什么没顺手补：`TimerManager` 在 executable target 里，XCTest 无法 `@testable import`。
要测它必须先改结构，两条路：

- **A（推荐，改动小）**：把「暂停/恢复/该不该进入休息」这些**决策**抽成一个不含 AppKit
  的 `SessionState`（`struct`，输入 `state + 事件 + 时间`，输出 `新状态 + 副作用枚举`），
  放进 `ICHRCore`，`TimerManager` 只负责把副作用变成 `NSTimer`、`NSPanel`、`NSSound`。
- **B（改动大）**：`Package.swift` 把 `src/` 拆成 `ICHRApp` 库 + 一个只含 `@main` 的
  executable target，测试直接 import `ICHRApp`。功能等价，但要动 `build.sh` 的产物路径。

**用户的选择是「要做就做最好」，于是选了 A 并做到底**：`core/SessionState.swift` 495 行、
35 项测试。B 没有选，因为抽出决策之后它只剩「搬运副作用」这层管道，收益抵不上动打包路径的
风险——但这层管道目前仍无测试，见第十节末尾。

## 十、第十三轮：把状态机搬进 ICHRCore（2026-10-28 午）

第九节 9.2 的 P1（`TimerManager` 零测试）已按方案 A 落地。用户的原话是
「要做就做最好」，所以没有先做一半，而是把整个状态机整体搬了出来。

### 10.1 改了什么

| 文件 | 变化 |
|---|---|
| `core/SessionState.swift`（新增 495 行） | 三态状态机：`phase` / `pauseCause` / `remaining` / `banked` / 长短休息 / 连续跳过 / 会议状态 / 宽限期起点。每个转换形如 `mutating func xxx(now: Date) -> [SessionEffect]`，**不引用 AppKit、不创建 Timer、不读 `Date()`、不写日志** |
| `core/TimerRules.swift` | 把 `breakGracePeriod`（1.5 秒淡入）从 `TimerManager` 移进来——它本来就是一条时间规则 |
| `src/TimerManager.swift` | 691 → 563 行。只剩：`Timer` 驱动、系统通知（锁屏/解锁/显示器休眠/唤醒）、会议与空闲轮询、遮罩、声音、日志、grace 动画、引导语轮换 |
| `Tests/ICHRCoreTests/SessionStateTests.swift`（新增） | 35 项，测试数 39 → **74** |

`SessionEffect` 是这次设计的核心：状态机不「做事」，只说明该做什么——
`workSessionStarted` / `breakStarted` / `breakFinished` / `breakInterrupted(meeting|wake)` /
`breakDismissed` / `breakDeferredToMeeting` / `imminentReminder` / `automaticPauseLifted`。
`TimerManager.perform(_:)` 是唯一的执行点。

对外接口保持不变：`state` / `remainingSeconds` / `currentPauseReason` / `menuBarText` /
`pauseStatusText` / `showsSkipButton` / `showsSkipHint` / `currentBreakTotalSeconds` 等
改成了 `session` 上的只读转发，**两个 SwiftUI 遮罩和 `AppDelegate` 一行没动**。
`TimerState` / `PauseReason` 保留为 `SessionPhase` / `PauseCause` 的 typealias，
所以 `switch` 分支照旧。

### 10.2 35 项测试覆盖了什么

锁屏暂停与解锁重置、显示器唤醒但仍在锁屏时不恢复、空闲阈值与「回到键鼠」、
暂停时机切换解除滞留暂停、会议中断休息、会议中到期改为待休息、会议结束的 5 秒倒计时、
会议结束恢复完整轮次、关掉会议暂停时解除暂停、唤醒三态、自然到期进休息、长短休息按轮次、
手动休息不计轮次、跳过计数与提示、按钮隐藏时 Esc 仍可退出、淡出期间被中断不被覆盖、
渐进提醒只响一次、工作时长缩短不延长当前轮次、休息中的进度环总量不被设置改动影响。

写测试的过程本身抓到一个设计问题：一开始我把「会议暂停被关掉」做成了独立的
`meetingPausingDisabled()`，于是设置变更有两个入口，测试里立刻就撞上了「该调哪个」的歧义。
已合并进唯一的 `configChanged(_:now:)`——所有可能把计时器卡住的设置（暂停时机、会议暂停、
工作时长）必须在同一个地方一起考虑，拆开就是漏一个的开始。

### 10.3 怎么验证的

- `swift test` **74 项全过**（原有 39 + 状态机 35）；
- `swift format lint --strict` 0 问题；`swift build` 无警告；
- `./build.sh ci` **10/10**；`codesign --verify --deep --strict` 通过；
- **端到端实跑**：把工作间隔临时改成 1 分钟、休息 5 秒，启动真实构建，日志依次出现
  `Break impending: 59s left` → `Break overlay triggered: full overlay` →
  `Break started: short 5s (session #1, manual=false)` → `Break overlay closed: timeout completed`
  → 下一轮开始。跑完已把用户的设置恢复原状（`workDurationMinutes` 未设置、`breakDurationSeconds=30`）。

### 10.4 仍然没有测试的部分

`TimerManager` 里剩下的那层「管道」：`Timer` 是否每秒触发、`perform` 是否把每个 effect

要覆盖它得走方案 B（拆 `ICHRApp` 库），收益比这次小得多，暂时不做。
